Harvest Time

Smart Farming Advisor — Product Design Review
July 2026 • Design Sprint Results

The Problem

Farmers juggle fragmented tools. Weather apps that don't understand crops. Soil data that doesn't connect to forecasts. Generic advice that ignores local conditions.

The result: guesswork where precision matters most.

A farmer's question is simple:
"What should I do this week?"

No existing tool answers it well.

🌤️ Weather Apps

Raw data. No crop context. "30% chance of rain" doesn't tell a farmer whether to spray.

🧪 Soil Reports

Lab results in PDFs. Disconnected from weather. No actionable advice.

📱 Farm Apps

Generic advice. One-size-fits-all. Don't know your fields, your crops, your schedule.

The Vision

An integrated platform that answers the farmer's question:
"What should I do this week, given my crops, my soil, and the weather coming?"

The Recommendation Engine

The heart of Harvest Time. A 6-step pipeline that fuses weather, crop phenology, and soil conditions into prioritized, personalized advice.

1

Rule Generation

Crop stage × weather × soil → raw recommendations

2

Override Application

Farmer's explicit overrides take precedence

3

Preference Filtering

Organic mode, skip categories, seasonal goals

4

Feedback Adjustment

>70% skip demotes category, >70% done boosts

5

Constraint Checking

Custom events block scheduling conflicts

6

Threshold Checking

Custom alert thresholds personalize triggers

🔄 Feedback Loop

Farmers respond to every recommendation: Done / Skip / Modified + optional note.

  • V1: Log only — builds training data
  • V2: Weighted heuristics — per-farmer skip rates adjust priority
  • V3: Pattern analysis — regional benchmarks

🎯 Rule-Based (Not ML)

Agronomist-defined rules per crop × growth stage × weather condition.

  • Auditable and predictable
  • No training data needed
  • Farmer feedback improves rules over time
  • ML transition at V3 with enough data

Offline & Reliability

Farmers work in fields with intermittent connectivity. This is a hard requirement, not nice-to-have.

💾 Cache-First Strategy

  • Last-known state always available
  • Weekly advice cached locally — works 7 days offline
  • Field data syncs when connectivity returns
  • Critical alerts attempt SMS even on 2G
  • Data freshness always visible ("4 hours old")

🔧 Circuit Breakers

  • 5 failures in 5 min → open circuit for 30 min
  • Half-open: 1 test request every 5 min
  • All external calls: 5s timeout (15s for batch)
  • Graceful degradation: stale data with timestamp

Success Metrics

📊 Engagement Metrics

  • ≥40% weekly return rate
  • ≥60% advisory interaction rate
  • ≥25% alert click-through rate
  • ≥50% field profile completion
  • ≥50% recommendation feedback rate

🎯 V1 Design Goal

Three farmer-authored interactions per week:

  1. Respond to recommendation (done/skip)
  2. Add field note
  3. Review history

This forms the ownership habit.

⚠️ Key Risks

  • Wrong recommendations erode trust → conservative rules, agronomist review
  • Weather data gaps in rural areas → gridded forecast models
  • Cold start — users don't fill in data → SSURGO auto-fill, GPS defaults
  • Notes feel like homework → capture-first, auto-tags, voice

✂️ If We Need to Cut

  • Multiple fields → one field per account
  • Notifications → in-app only
  • Weather translation → basic interpretation
  • SSURGO → pure manual entry

Never cut: The weekly advisory.
